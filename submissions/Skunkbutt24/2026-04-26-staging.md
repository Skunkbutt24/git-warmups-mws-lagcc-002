## What I learned or re-learned
I learned that the staging area is the place where Git holds changes before they become part of a commit. `git add` puts a file into the staging area, but `git commit` saves the staged change into the project history. I also learned that `git restore --staged <file>` removes a file from the staging area without deleting the actual file from my folder.

If I run `git add .`, Git stages all current changes in the folder instead of only one specific file. To stage a deletion of a tracked file, I can delete the file and then run `git add <file>`. `git restore <file>` discards unstaged changes from the working file, while `git restore --staged <file>` only unstages the file.
