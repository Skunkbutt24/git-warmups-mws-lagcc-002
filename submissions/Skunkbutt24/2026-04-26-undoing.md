# 2026-04-26-04 - undoing

## Drill I did
undoing.md

## What I ran
git status  
echo "oops" >> README.md  
git status  
git restore README.md  
git status  

echo "wait" >> README.md  
git add README.md  
git status  
git restore --staged README.md  
git status  
git restore README.md  
git status  

echo "test" > scratch.txt  
git add scratch.txt  
git commit -m "fix: tpyo in message"  
git commit --amend -m "fix: typo in message"  
git log --oneline -1  
git rm scratch.txt  
git commit -m "chore: remove scratch file"  

## What I learned or re-learned
The difference between `git restore <file>` and `git restore --staged <file>` is that `git restore <file>` removes the actual unstaged edit from the working file, while `git restore --staged <file>` only removes the file from the staging area but keeps the edit in the file.

`git commit --amend` changes the most recent commit. In this drill, I used it to fix a typo in the last commit message from `fix: tpyo in message` to `fix: typo in message`.

Out of the three scenarios, I think I will use `git restore --staged <file>` most often because I may accidentally stage a file before I am ready to commit it.

## What still feels slow
I still need more practice deciding when to use `git restore`, `git restore --staged`, and `git commit --amend`.
